# End-to-end test of stele v1 on this repository

Issue #13, run on 2026-10-23.

## Setup

- stele at 32b83ae, built with `go build -o <bin>/stele.exe ./cmd/stele` and put first on `PATH` (never `go install`).
- Claude Code 2.1.309 (the VS Code extension's `claude.exe`), headless: `-p`, `--model haiku`, `--permission-mode acceptEdits`, `--disallowedTools Bash`, `--output-format stream-json --verbose --debug-file`.
- Windows 10, Git Bash.
- A throwaway `git clone` of this repo (`<clone>`), with the `stele.md` committed here. `stele init`, then `stele compile`, then commit.
- Every hook payload was logged by a second, logging-only hook in `<clone>/.claude/settings.local.json`. Claude Code runs both hooks, so the logger sees exactly what stele sees.

Before any agent ran:

- `stele check --all` on the clone: `10 rules valid`, `checked 91 files: no violations`.
- Positive control: a probe file importing `net/http` and `os/exec` and calling `os.Exit` and `fmt.Println` gave 4 errors from rules 8, 9 and 10, exit 1. The three patterns are live.

### `stele init`

```
created .stele/.gitignore
added stele hooks (PreToolUse, PostToolUse) to .claude\settings.json
stele init: kept the existing stele.md
10 rules: 0 matched by text, 0 by position, 10 new, 0 dropped
```

### Blocked on the first write, then writes (turn 1)

Prompt: add two Example test files in `internal/scope`, one at a time, with the Write tool.

```
TOOL_USE Write internal/scope/example_applies_test.go
RESULT err=True  PreToolUse:Write hook error: stele paused this write to internal/scope/example_applies_test.go: this project has rules for it that you have not seen in this turn. ... (7 rules)
TOOL_USE Write internal/scope/example_match_test.go
RESULT err=True  PreToolUse:Write hook error: stele paused this write to internal/scope/example_match_test.go ...
TEXT     The write hook paused both writes and showed project rules I hadn't seen this turn. My files follow them ...
TOOL_USE Write internal/scope/example_applies_test.go
RESULT err=None  File created successfully
```

The model sent the second Write 1.2 s after the first was denied, so it fell inside the 3 s window and was denied too (documented behaviour). The retry went through.

The post-write check then blocked the new file: its `fmt.Println` lines broke rule 10 as first written, `internal/**/*.go` must not print. The block named lines 11, 12 and 14, which were correct. The model did not work around the rule. It stopped, explained the conflict (Go Example tests need `fmt.Println`), and offered three options. That is the behaviour we want. The conflict was in the rule, not in stele: see "What to change".

### Same turn goes through; a new turn shows the rules again (turn 2)

Turn 2 resumed the same session with a new prompt (`--resume <id>`). Logged payloads:

```
turn 1: session c1a7517c  prompt_id 14c0d16f-...
turn 2: session c1a7517c  prompt_id 2704c337-...
```

- The session id was kept and the prompt id changed, so turn 2 is a real new turn. Its first Edit to `internal/scope/scope.go` was denied with the rules again, although the agent had seen the same rules in turn 1.
- Later in turn 2, two more Edits to the same file got no pre-write output and went through: same turn, no new rules.

### Flagged right after a write, and the agent fixes it (turn 2)

Prompt: insert `if len(patterns) > 1000 { os.Exit(3) }` at the top of `scope.Applies`, then do what stele says.

- The retried Edit went through, and PostToolUse returned `decision: block`: `stele checked your write to internal/scope/scope.go: it breaks these project rules ...`. The model's next message was "The check flagged `scope.go:45`".
- Line 45 is exactly the `os.Exit(3)` line: the patch's `newStart` is 41, followed by 3 context lines and the `if`.
- The model reverted both edits. `git diff` on the clone was empty afterwards.
- The Edit that added `"os"` to the imports was not flagged. It added no violation, and the older `os.Exit` was not in its lines.

### `stele check` catches a broken rule in CI

Run locally with the same command as the CI job. A branch adds `internal/scope/broken.go` calling `os.Exit(1)`:

```
$ stele check --base main
internal/scope/broken.go:7:3: error d4e09005-a875-4772-8f9c-9edfc4a7e32f "Packages under internal/ never exit the process or print. Th…": packages under internal/ return errors; only cmd/stele exits or prints
10 rules valid
checked 1 file: 1 error
exit=1
```

Changing one word in `stele.md` without recompiling gives `stele check: stele.lock is out of date with the rules: run stele compile and commit stele.lock` with exit 1. Restoring the file gives exit 0.

This PR also adds a `stele` job to CI (`go run ./cmd/stele check --base origin/${{ github.base_ref }}`, pull requests only), so from now on every PR is checked against `stele.md`.

## Findings

- **`structuredPatch` is real.** Claude Code 2.1.309 sends it on every Edit and Write in `tool_response`, the open question from #29.
  - Edit `tool_response` keys: `filePath`, `newString`, `oldString`, `originalFile`, `replaceAll`, `structuredPatch`, `userModified`.
  - Write `tool_response` keys: `content`, `filePath`, `originalFile`, `structuredPatch`, `type`, `userModified`. `structuredPatch` is `[]` for a new file.
  - Each hunk is `{"oldStart", "oldLines", "newStart", "newLines", "lines"}`, and each line is prefixed `' '`, `'-'` or `'+'`:
    ```json
    [{"oldStart": 41, "oldLines": 6, "newStart": 41, "newLines": 9,
      "lines": [" func Applies(patterns []string, file string) bool {",
                "+  if len(patterns) > 1000 {", "+    os.Exit(3)", "+  }",
                "   if len(patterns) == 0 {", ...]}]
    ```
  - The `lines` show tabs as spaces. stele reads only the prefixes and counts, so this does not matter.
  - stele's line for the block matched the patch exactly.
- **`--resume` keeps `session_id` and gives a new `prompt_id`.** "Once per turn" works across a resumed session.
- **Parallel writes:** in both turns the model sent its next write right after a deny, inside the 3 s window, so both were denied and both retried. This is expected, and it cost one extra round trip per turn.
- **No Bash attempts.** Bash was disallowed for the runs. The only `permission_denials` in the results are stele's own denies, which Claude Code counts as permission denials.
- **Hook latency:** stele hook took 100–150 ms per call (from `--debug-file`, e.g. `PreToolUse:Write [stele hook ...] finished with status 0 (132ms)`).
- **Cost:** turn 1 $0.0107, turn 2 $0.0154. $0.026 in all, with haiku.

## What didn't work, and what to change

1. **Scopes cannot exclude files.** Rule 10 was first scoped to `internal/**/*.go` with a pattern for `os.Exit` and `fmt.Print`. Go Example tests need `fmt.Println`, so it broke the first test file the agent wrote. A glob has no `!**/*_test.go`. The committed rule now checks only `os.Exit`. Proposed change: exclusions in `scope` (for example a `!` prefix).
2. **`pattern` values are unquoted.** `parseRule` strips one pair of outer quotes from every value, `pattern` included. A pattern such as `"net/http"` loses its quotes and matches `net/http` anywhere. The import rules here start with `(?m)` and end with `$` to avoid this. Proposed change: no unquoting for `pattern`, or say so in the README. Fixed in #40.
3. **The version stamp is a pseudo-version.**
   - A `go build` in a git checkout stamps `v0.0.0-<date>-<commit>`, not `devel`. The committed `.claude/settings.json` says `--installed=v0.0.0-20261023085801-32b83aefb0cb`.
   - Anyone running a stele built from another commit gets "run stele init to update them" once per session, and re-running init rewrites the committed file.
   - Proposed change: treat pseudo-versions like `devel` (no warning), or stamp only tagged versions.
4. **Claude Code labels the deny "hook error".** The agent reads `PreToolUse:Write hook error: stele paused this write ...`. The model handled it well, but the word "error" frames an intended pause as a failure. That framing comes from Claude Code, not stele. Worth watching with other models.
5. **The block reason is not in `stream-json`.** It is only in the debug log and in what the model says next. This makes headless runs harder to assert on. No stele change is needed.
6. **Agent worktrees under `.claude/worktrees/`** (reasoned, not tested): a worktree on a branch without `stele.md` finds the main checkout's `stele.md` by walking up. Paths then start with `.claude/worktrees/<id>/`, so `**/*.go` rules apply but `internal/**` and `cmd/stele/...` scopes do not. Worktrees made from main after this PR have their own `stele.md` and are not affected.

7. **`stele init` warns inside a nested git worktree.**
   - Running init in `.claude/worktrees/<id>/` printed "this is not the repository root (C:\Users\Nacer\stele)". Yet the worktree has its own `.git` file and is a root.
   - Proposed change: no warning when the current directory itself holds `.git`.

## What this PR turns on

With `stele` on `PATH`, anyone running Claude Code in this repository now gets:

- the first write per turn denied with up to 7 rules;
- the post-write checks from rules 8, 9 and 10.

Without `stele` on `PATH`, every Write and Edit runs a hook that fails with "command not found". The write still goes through (README, Limits 1), but the hook error shows on each write.
